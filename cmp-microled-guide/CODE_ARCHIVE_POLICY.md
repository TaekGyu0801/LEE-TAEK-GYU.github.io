# CMP Micro-LED — Code Archive Policy

Updated: 2026-08-28

## 원칙

각 Phase는 다시 여러 개의 **소단원(Subunit)** 으로 나눈다. 결과 문서만 남기지 않고, 실제 실행 코드·입력·결과·검증 기록을 연결한다. 다만 같은 실행 deck을 여러 소단원이 함께 사용하는 경우에는 코드를 중복 업로드하지 않고 **단일 원본(canonical copy)** 을 한 곳에만 보관한다.

## 소단원 코드 상태

소단원마다 아래 3가지 중 하나를 명확히 표시한다.

1. **`CODE 필요` (`codePolicy=required`)** — 이 소단원만의 실행 코드가 있으며 실제 `.cmd` 등이 첨부되어야 한다.
2. **`CODE 공유` (`codePolicy=shared`)** — 다른 소단원의 동일 실행 deck을 그대로 사용한다. `sharedFrom`으로 원본 소단원을 지정하고 중복 업로드하지 않는다.
3. **`CODE 불필요` (`codePolicy=none`)** — 문헌 검토, 해석, 판정, 파라미터 provenance 등 실행 코드 자체가 없는 작업이다.

### 공유 코드 규칙

- 공유 대상 코드는 반드시 **하나의 canonical 소단원**에 실제 파일로 저장한다.
- 공유 소단원은 `sharedFrom: P#-##` 형식으로 원본을 가리킨다.
- 원본 소단원에 실제 Command가 아직 없으면 공유 소단원도 재현성 완료로 보지 않고 **`공유원 CODE 미첨부`** 로 표시한다.
- 같은 `.cmd`를 여러 폴더에 복사하여 중복 관리하지 않는다.
- 코드가 같고 결과 해석만 다른 경우에는 보통 `CODE 공유`가 적절하다.
- 입력값, bias 조건, mesh, physics 설정 중 하나라도 실제 실행 deck이 달라졌다면 별도 `CODE 필요`로 분리한다.

## 소단원 완료 조건

각 소단원에는 가능한 경우 다음 5종을 연결한다.

1. `README / 목적` — 무엇을 검증하는 작업인지
2. `PARAMETER / INPUT` — 입력값, 단위, 출처, 미확정 항목
3. `COMMAND` — 실제 실행에 사용한 `.cmd`, `.par`, `.tcl`, `.py`, `.plt` 등
4. `RESULT` — 그래프, 수치표, 로그 요약, 결과 이미지
5. `VALIDATION / INTERPRETATION` — 결과 해석, Gate 판정, 문제점, 다음 작업

### Command 의무 규칙

- `CODE 필요` 소단원은 **실행한 최종 Command 파일이 없으면 재현성 완료로 처리하지 않는다.**
- `CODE 공유` 소단원은 자체 복사본이 없어도 되지만 canonical 소단원의 실제 Command가 존재해야 한다.
- `CODE 불필요` 소단원은 코드 누락으로 간주하지 않는다.
- 원본과 수정본이 둘 다 의미가 있으면 둘 다 보관하고 파일명/README에 역할을 표시한다.
- PPT Appendix에는 기억이나 재작성 코드가 아니라 **GitHub에 보관된 실제 실행 Command**를 사용한다.

## 권장 폴더 형식

```text
P#/<subunit>/
├─ README.md
├─ INPUT.md
├─ commands/
│  ├─ *.cmd
│  ├─ *.par
│  └─ ...
├─ RESULTS.md
├─ validation/
└─ issues/
```

공유 코드 소단원은 `commands/`를 중복 생성하는 대신 manifest에서 canonical 소단원을 참조한다.

## 파일을 전달받았을 때의 분류 규칙

사용자가 `.cmd`, 로그, 결과 이미지, Excel, 터미널 출력 등을 전달하면 별도 경로 지시가 없어도 현재 연구 맥락을 기준으로 해당 `Phase → Subunit → 파일 종류`에 분류한다. 동일 코드인지 새 실행 deck인지 판단하여 `CODE 필요 / CODE 공유 / CODE 불필요` 중 하나를 지정한다. 불확실할 때만 사용자에게 확인한다.

## 재현성 우선순위

`실제 실행 코드 → 입력 파라미터와 출처 → 실행 결과 → 해석/판정` 순으로 연결한다. 중복 파일 수보다 **어떤 결과가 어떤 실제 실행 deck에서 나왔는지 추적 가능한지**를 우선한다.
